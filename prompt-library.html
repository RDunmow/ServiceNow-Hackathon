1a. Quick review

Use it: For most teams. A short brief that catches the big gaps fast.

Prompt
We're building an app at a hackathon. Here's a summary of our plan.

Problem: Employees report office problems by email, chat and in the
corridor. Reports get lost or duplicated, and people never hear back.

Users: reporters (any employee), fixers (facilities team members) and
a coordinator who triages new issues.

Headline: Anyone can report an office problem in 30 seconds, and it
reaches the right team without anyone sorting an inbox.

How it works: a reporter submits an issue (description and location).
Setting a category routes it to a team through a Category routing
table. Fixers resolve it with resolution notes, and the reporter
confirms the fix to close it. Reporters can't change category,
priority or assignment.

Day 1 must have: Issue table, report form, routing by category,
resolve with notes.
Day 2 should have: notifications, role-based lists, then an AI skill
that suggests category and priority, and an AI agent that flags
possible duplicates.

Please:
1. Point out any gaps, contradictions or risks.
2. Ask us any questions you need answered, one at a time.
3. Suggest the order we should build it in, one feature per step.

Reply in the chat only. Don't create a plan or make any changes yet.

1b. Full review

Use it: When you want a thorough check of the whole plan. It is long, so give Build Agent a moment.

Prompt
We're building an app at a hackathon. Below is our team's full plan.

Please:
1. Summarise what you understand we want to build.
2. Point out any gaps, contradictions or risks in the plan.
3. Ask us any questions you need answered, one at a time.
4. Suggest the order we should build it in, one feature per step.

# Team plan: Workplace Issue Reporter

## 1. The problem
Employees report office problems such as broken lights, faulty desks and heating failures by email, chat messages or by stopping someone in the corridor. Reports get lost, the same problem is reported five times, and nobody knows whether anything is happening. The facilities coordinator spends the first hour of every day reading and forwarding messages.
In one sentence: Office problems are reported in too many places, so they're slow to reach the right team and people never hear back.

## 2. The people

| Role | What they need to do | How often |
|---|---|---|
| Reporter (any employee) | Report a problem, check its progress, hear when it's fixed | Occasionally |
| Fixer (member of a facilities team) | See issues for their team, update progress, resolve them | Daily |
| Coordinator | Review new issues, correct category or priority, manage teams | Daily |

## 3. The finished product
Headline: Anyone can report an office problem in 30 seconds, and it reaches the right team without anyone sorting an inbox.
Demo story: table:
1. Alex notices the heating isn't working in meeting room 3B and reports it in a couple of sentences.
2. The issue is categorised as Heating and cooling, marked High priority, and routed to the Building services team. Two similar reports from the same floor are flagged as possible duplicates.
3. Jordan in Building services picks it up, fixes it, and resolves it with a note.
4. Alex gets a notification that it's fixed.

## 4. Scope

| Must have (day 1) | Should have (day 2) | Won't have |
|---|---|---|
| Issue table, report form, routing by category, resolve with notes | Notifications, "My issues" list, coordinator and team views, AI triage skill and agent | Mobile app, building management system integration, reporting dashboards |

## 5. Data

Issue table:

| Field | Type | Choices or referenced table | Mandatory? |
|---|---|---|---|
| Number | Auto-number (prefix WPI) | | Yes |
| Short description | Text | | Yes |
| Description | Long text | | Yes |
| Location | Reference | cmn_location | Yes |
| Category | Choice | Electrical, Plumbing, Heating and cooling, Furniture, Cleaning, Other | No (set during triage) |
| Priority | Choice | 1 - Urgent, 2 - High, 3 - Normal, 4 - Low (default Normal) | Yes |
| State | Choice | New, Assigned, In progress, On hold, Resolved, Closed | Yes |
| Reported by | Reference | sys_user (default: current user) | Yes |
| Assignment group | Reference | sys_user_group | No |
| Assigned to | Reference | sys_user | No |
| Resolution notes | Long text | | When resolved |
| Work notes | Journal | | No |

Category routing table:

| Field | Type | Choices or referenced table | Mandatory? |
|---|---|---|---|
| Category | Choice | Same choices as on Issue | Yes |
| Assignment group | Reference | sys_user_group | Yes |

Relationship: Each category routes to one assignment group. Many issues can share a location.

## 6. The process
- Trigger: A reporter submits an issue. It starts in the New state.
- Steps: When a category is set, the issue is assigned to that category's group and moves to Assigned. A fixer sets it to In progress, then to Resolved with resolution notes. The reporter can confirm the fix to close it; the coordinator can also close it.
- States: New → Assigned → In progress → (On hold) → Resolved → Closed.
- Notifications: The reporter when the issue is resolved; the coordinator straight away for anything Urgent; the assignment group when an issue is assigned to them.

## 7. Rules and logic
- When the category is set or changed, set the assignment group from the Category routing table and set the state to Assigned.
- Never allow an issue to be resolved without resolution notes.
- Assigned to must be a member of the assignment group.
- Reporters can't change the priority, category or assignment.

## 8. Where people work
- Reporters: a short report form (short description, description, location) and a "My issues" list.
- Fixers: a list of open issues assigned to their groups.
- Coordinator: a list of New issues, and all open issues grouped by location.

## 9. Who can see and do what

| Role | Create | Read | Update | Delete |
|---|---|---|---|---|
| Reporter | Issues | Own issues | Own issues: description only, and confirming a fix | None |
| Fixer | None | All issues | Issues assigned to their groups | None |
| Coordinator | Issues, Category routing | All | All issues and Category routing | Category routing |

## 10. Test scenarios

| Scenario | Expected result |
|---|---|
| Report an issue as a reporter | Issue created as New; appears in the coordinator's list |
| Coordinator sets the category to Plumbing | Assigned to Building services; state is Assigned |
| Fixer resolves an issue with no resolution notes | Blocked with a clear message |
| Report an Urgent issue | Coordinator notified straight away |
| Reporter tries to change the assignment group | Not allowed |

## 11. How we'll show value
We'd measure time from report to assignment (currently up to a day), the number of duplicate reports, and how often people chase for updates.

## 12. Assumptions and risks
Assumes each category maps to one team. Location data already exists on the platform. Integration with building systems is out of scope.

## 13. Where could AI help?

| Where people spend time today | What AI could do | Skill or agent? | What a person stays in control of |
|---|---|---|---|
| The coordinator reads every new report to choose a category and priority | Read the description and suggest a category, priority and one-line summary | Skill | The coordinator can change any suggestion |
| Several people report the same problem | Find similar open issues at the same location and flag possible duplicates | Agent (uses the skill) | The coordinator decides whether to merge or close duplicates |

Reply in the chat only. Don't create a plan or make any changes yet.

2. Build the foundation: data and roles

Use it: First build. Check both tables and their fields before moving on.

Prompt
Create a scoped app called Workplace Issue Reporter.

Purpose: let employees report office problems in one place and route
them to the right facilities team.

Roles:
- workplace_reporter: can create issues and read their own issues.
- workplace_fixer: can read all issues and update issues assigned to
  their groups.
- workplace_coordinator: can read and update all issues, and manage
  the Category routing table.

Tables:
1. Issue, with fields:
   - Number (auto-number with prefix WPI)
   - Short description (string, mandatory)
   - Description (long string, mandatory)
   - Location (reference to cmn_location, mandatory)
   - Category (choice: Electrical, Plumbing, Heating and cooling,
     Furniture, Cleaning, Other)
   - Priority (choice: 1 - Urgent, 2 - High, 3 - Normal, 4 - Low;
     default 3 - Normal)
   - State (choice: New, Assigned, In progress, On hold, Resolved,
     Closed; default New)
   - Reported by (reference to sys_user, default current user)
   - Assignment group (reference to sys_user_group)
   - Assigned to (reference to sys_user)
   - Resolution notes (long string)
   - Work notes (journal input field, visible to fixers and coordinators)
2. Category routing, with fields:
   - Category (same choices as Issue, mandatory, unique)
   - Assignment group (reference to sys_user_group, mandatory)

Set up access controls to match the roles above.
Create a plan first and wait for my approval before building.

3. Add the process

Use it: Once the foundation is checked.

Prompt
In the Workplace Issue Reporter app, add the issue process:

- New issues start in the New state.
- When the Category is set or changed, look up the Assignment group
  in the Category routing table, set it on the issue, and set the
  State to Assigned.
- Fixers can move an issue to In progress, On hold or Resolved.
- The reporter can confirm a Resolved issue is fixed, which sets the
  State to Closed. The coordinator can also close Resolved issues.

Don't change the table structure. Show me the plan before making changes.

4. Add the rules

Use it: After the process works.

Prompt
In the Workplace Issue Reporter app, add these rules to the Issue
table. Each should stop the record being saved and show a clear
message to the user:

1. Never allow an issue to be set to Resolved without Resolution notes.
2. Assigned to must be a member of the Assignment group.
3. Users with only the workplace_reporter role can't change Priority,
   Category, Assignment group or Assigned to.

Show me the plan before making changes.

5. Add notifications

Use it: Same conversation as Prompt 4, or a new one.

Prompt
In the Workplace Issue Reporter app, add these notifications:
- Email the Reported by user when their issue is Resolved, including
  the Resolution notes and a reminder to confirm the fix.
- Email users with the workplace_coordinator role as soon as an issue
  is created or changed to 1 - Urgent.
- Email the Assignment group when an issue is assigned to them.

6. Shape the user experience

Use it: Attach a photo of your screen sketches.

Prompt
In the Workplace Issue Reporter app, improve the experience for each
role. I've attached our sketches.

For reporters:
- A short report form with only Short description, Description and
  Location.
- A "My issues" list showing their issues, newest first, with State.

For fixers:
- A list of open issues assigned to their groups, highest priority
  first.

For coordinators:
- A list of New issues.
- All open issues grouped by Location.

Show me the plan before making changes.

7. Create test data

Use it: Same conversation as Prompt 6, or a new one.

Prompt
Create sample data for the Workplace Issue Reporter app so we can
test it. Use fictional names and values only.

- 3 assignment groups: Building services, Workplace team and
  Cleaning services.
- Category routing records: Electrical, Plumbing and Heating and
  cooling to Building services; Furniture and Other to Workplace team;
  Cleaning to Cleaning services.
- 3 locations, if none exist.
- 4 test users: 2 with workplace_reporter, 1 with workplace_fixer (a
  member of Building services) and 1 with workplace_coordinator.
- 15 issues across every State and Category, written the way real
  people describe problems. Include 3 issues about the same heating
  problem at the same location, and a few with no Category yet.

| Coordinator sets the category to Plumbing | Assigned to Building services; state is Assigned |

Day 2: add a feature

Use it: Once the must-have scope is tested. This example adds a way to reopen issues.

Prompt
In the Workplace Issue Reporter app, add a way for reporters to reopen
an issue.
It should let the Reported by user say a Resolved issue isn't fixed,
which moves it back to Assigned and adds their comment to Work notes.
They can only do this before the issue is Closed.
Don't change the existing routing or the Category routing table.
Show me the plan before you make changes.

Start each in a new conversation, in this order. Mentors: check Now Assist for App Engine is enabled first.

Find AI opportunities

Use it: Before building any AI. Compare its ideas with section 13 of your plan.

Prompt
Review the Workplace Issue Reporter app, including its tables, roles,
process and sample data. Identify where an AI skill or AI agent would
add the most value. For each idea, tell us what it would do, whether
it should be a skill or an agent, and what a person should stay in
control of. Recommend the quickest win. Don't build anything yet.

Build the skill

Use it: Then test it in Now Assist Skill Kit before publishing.

Prompt
In the Workplace Issue Reporter app, create an AI skill called
Issue triage suggestion.

Input: the Short description, Description and Location of an Issue.

Output:
- A suggested Category (one of: Electrical, Plumbing, Heating and
  cooling, Furniture, Cleaning, Other)
- A suggested Priority (1 - Urgent, 2 - High, 3 - Normal, 4 - Low),
  where Urgent means a risk to safety or a building that can't be used
- A one-sentence summary of the problem
- A short reason for the suggestions

Add a field called AI summary (string) to the Issue table to hold the
summary. Coordinators can use the skill from the Issue form and must be
able to change any suggestion.

Show me the plan before building.

Refine the skill

Use it: If the suggestions are off after testing.

Prompt
Update the Issue triage suggestion skill in the Workplace Issue
Reporter app: anything mentioning water leaking onto electrical
equipment is always 1 - Urgent and Electrical. Anything about a
building that can't be used safely is always 1 - Urgent.

Build the agent

Use it: Once the skill is published. Then test it in AI Agent Studio and activate its triggers.

Prompt
In the Workplace Issue Reporter app, create an AI agent called
Issue triage agent.

Goal: when a new Issue is created without a Category, triage it so it
reaches the right team quickly.

The agent should:
1. Use the published Issue triage suggestion skill to get a category,
   priority and summary.
2. Set the Category, Priority and AI summary on the Issue. Setting the
   Category routes it through the existing Category routing rule.
3. Search for open Issues at the same Location with a similar
   description. If it finds any, set a new field called Possible
   duplicate of (reference to Issue) and mention them in a work note.
4. Add an entry to the Work notes field explaining what it did and why.

The agent must never resolve, close or delete an Issue, or change
Reported by. Coordinators decide what to do with possible duplicates.

Show me the plan before building.

When you need help

Get a better prompt

Use it: When you know what you want but not how to ask.

Prompt
I want coordinators in the Workplace Issue Reporter app to see which
locations have the most open issues. Suggest the ideal prompt I should
give you to build this, and tell me about any common pitfalls.

Let Build Agent interview you

Use it: When an idea is still fuzzy.

Prompt
We want the Workplace Issue Reporter app to help facilities teams
plan regular maintenance, as well as fix problems. Before you plan
anything, interview me. Ask one question at a time until you
understand what we need, then summarise it back to me.

Report a bug

Use it: When something doesn't work as expected. Give the steps, the expected result and what happened.

Prompt
In the Workplace Issue Reporter app, routing isn't working.

What I did: logged in as the coordinator, opened an issue in the New
state with no Category, and set the Category to Plumbing.
What I expected: Assignment group set to Building services and State
changed to Assigned.
What happened: Category saved, but Assignment group is empty and
State is still New.

Find the cause and explain it before changing anything.

Fix the user interface

Use it: Attach a screenshot of the page.

Prompt
Here's a screenshot of the report form in the Workplace Issue Reporter
app. Location should be the first field, Description is missing, and
reporters can see Assignment group, which should be hidden from them.
Please fix this.

Explain what was built

Use it: When you need to understand or demo a feature.

Prompt
Explain how category routing works in the Workplace Issue Reporter
app, which records you created for it, and where I can find them.
