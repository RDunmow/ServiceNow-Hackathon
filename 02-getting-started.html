Getting started

What Build Agent is

Build Agent is an AI agent built into the ServiceNow AI Platform. You describe the app you want in plain language, and it plans and builds it: tables, forms, logic, and user interface.

Two things to keep in mind:

  • It's a partner, not a vending machine. Build Agent isn't designed as a one-shot tool. You review its plan, test what it builds, and steer it. The best results come from teams who stay involved.
  • It builds real platform metadata. Everything it creates is a standard ServiceNow app, tracked in update sets, that you can open, inspect and change yourself.

Before you start

Check these with your team before your first prompt:

Ready to start

Open Build Agent

  1. In your instance, navigate to All > App Development > ServiceNow Studio.

  2. The Build Agent chat panel opens by default in a new ServiceNow Studio session.

  3. If it doesn't appear, ask a mentor.
Tip

Studio or IDE? Build Agent also runs in the ServiceNow IDE, which is code-first. For this hackathon, use ServiceNow Studio unless a mentor suggests otherwise. Studio gives you stronger guardrails and visual previews of changes.

Your first conversation

A typical first build follows this path:

  1. Describe your app. Tell Build Agent what you're building, who it's for, and what it must do. Guide 3 shows how to turn your plan into prompts.

  2. Answer its questions. For broader ideas, Build Agent may ask clarifying questions first. Answer them properly. This saves time later.

  3. Review the plan. Build Agent proposes a plan before it builds. Read it as a team. Is anything missing? Anything you don't need? Ask for changes in the chat.

  4. Approve the plan. When you're happy, select Approve plan. Build Agent then builds the app.

  5. Check the result. Build Agent shows a success message and the details of your app in the chat panel. Ask it, "How do I access and test this app?" if you're not sure where to go next.

Checkpoints: your safety net

Each time you approve a plan, Build Agent automatically creates a checkpoint. A checkpoint groups the changes made in that step, and you can roll back to it at any point in the conversation.

Every change is also recorded in the conversation change log, so you can see exactly which files Build Agent changed and why.

This means you can experiment safely. If a change goes wrong, you roll back rather than starting again. Guide 4 covers how.
