AI vibe coding primer

Before you build, it helps to understand what's happening when you type a prompt into Build Agent. Ten minutes here will make every prompt you write better.

What is vibe coding?

"Vibe coding" is a nickname for building software by describing what you want in plain language and letting AI do the building. You don't write the code yourself. You describe, review, test and steer.

It's fast, and it lets people who don't write code build real apps. But the AI only builds what it understands from your words. The skill you need isn't coding; it's explaining clearly.

How an AI agent works

Build Agent is built on a large language model (LLM). An LLM is very good at one thing: working out a sensible response to the text in front of it. On its own, it can only produce text.

An agent is an LLM connected to tools, working in a loop:

  1. Read. It reads your request and anything else in front of it.

  2. Plan. It works out the steps needed.

  3. Act. It uses tools to carry out a step, for example creating a table or writing a script.

  4. Check. It looks at the result, then decides the next step.

  5. Repeat until the job is done, or it needs you.

Build Agent's tools work on the ServiceNow AI Platform, so what it creates is a standard app: tables, forms, logic and access controls you can open and change yourself. It shows you a plan and waits for you to select Approve plan before it builds.

The context window is everything the AI can see at one moment. Think of it as a whiteboard. Everything on the whiteboard shapes what it does next:

  • your prompts in this conversation
  • its own replies and plans
  • the parts of your app it has read
  • the results of the tools it has used

Anything that isn't on the whiteboard, the AI doesn't know. It can't read your mind, your team's planning document, or a conversation you had over coffee.

Tokens

Text in the context window is measured in tokens. A token is a chunk of text, often part of a word. In English, a token averages roughly three-quarters of a word. The whiteboard holds a large but limited number of tokens.

Why long conversations go wrong

As a conversation grows, the whiteboard fills up. Early details get crowded out or summarised, and the AI's attention is spread across more material. This is why a long conversation that started well can drift: it "forgets" a rule you gave it an hour ago, or mixes up two features.

New conversation, fresh whiteboard

When you start a new conversation, the whiteboard is wiped. The AI doesn't remember the chat. But your app is still there on the instance, and Build Agent can read it. A new conversation loses the chat, not the work.

That's why the guides tell you to build one feature per conversation: each conversation starts with a clean whiteboard containing only what matters for that feature.

What this means for your prompts

Because... ...do this
The AI only knows what's in the context window Put everything it needs in the prompt: who, what, why, and the rules.
Gaps get filled with guesses Be specific. Name tables, fields, field types and roles.
Long conversations drift One feature per conversation. Mark it complete, then start fresh.
A new conversation remembers nothing Restate the key facts each time: the app name and what must not change.
The AI can be confidently wrong Review the plan before you approve it, and test what it builds.
The same prompt can give different results Don't expect your app to match another team's exactly. That's normal.
Mistakes happen Use checkpoints to roll back rather than arguing with it.

Good to know

  • It's not a search engine. The AI generates a response; it doesn't look one up. If it tells you something about the platform, check it.
  • It doesn't learn from your conversation. Correcting it helps for the rest of that conversation only. Put lasting rules in every relevant prompt.
  • Plain language is fine. Precise language is better. "A reference field to sys_user" beats "a field for the person".
  • You're still the developer. Build Agent does the typing. You decide what's built, check it works, and own the result.

Glossary

Term Meaning
Prompt The instruction you type to the AI.
LLM Large language model: the AI that reads and writes text.
Agent An LLM that can use tools and work through steps towards a goal.
Tool Something the agent can do, such as create a table or run a script.
Context window Everything the AI can see at one moment: its working memory.
Token A chunk of text used to measure the context window.
Hallucination When the AI states something that isn't true, with confidence.
Checkpoint A saved point in a Build Agent conversation that you can roll back to.
