Adding an agent or skill

Once your core app works, Build Agent can add AI to it. It can create custom AI skills, AI agents and agentic workflows for your app, along with their instructions, tools, access controls and supporting scripts.

This guide continues the Workplace Issue Reporter example from Guide 3.

Skill, agent or workflow?

You don't have to tell Build Agent which one you need; it works that out from your prompt. It still helps to know the difference when you plan.

What it does Workplace Issue Reporter example
Skill Does one AI task well, such as summarising, classifying or drafting text. Read an issue description and suggest a category, priority and summary.
AI agent Works towards a goal: it reasons about what to do and uses tools to take action. Triage new issues: use the skill, look for similar open issues, flag duplicates and record what it did.
Agentic workflow Several AI agents working together on a bigger process. Not needed for this app. Keep it simple at a hackathon.

Start with a skill. It's quicker to build and test, and an agent can use it later.

Before you start

Ready to add AI

Keep people in control

Good AI features help people do their jobs; they don't take decisions away from them. For every skill or agent, decide:

  • What it can do on its own. For example: suggest a category, add a work note.
  • What a person must confirm. For example: closing or merging duplicates.
  • What it must never do. For example: resolve or close an issue, or change who reported it.
  • How people see what it did. For example: a work note explaining its reasoning.

Put these in your prompts. They also make a strong point in your demo.

Step 1: Ask Build Agent where AI could help

Before building, check your plan against Build Agent's ideas. Start a new conversation:

Prompt
Review the Workplace Issue Reporter app, including its tables, roles,
process and sample data. Identify where an AI skill or AI agent would
add the most value. For each idea, tell us what it would do, whether
it should be a skill or an agent, and what a person should stay in
control of. Recommend the quickest win. Don't build anything yet.

Compare its answer with section 13 of your plan. If it suggests something better, update your plan. Then mark the conversation complete.

Step 2: Build the skill

Start a new conversation.

Prompt
In the Workplace Issue Reporter app, create an AI skill called
Issue triage suggestion.

Input: the Short description, Description and Location of an Issue.

Output:
- A suggested Category (one of: Electrical, Plumbing, Heating and
  cooling, Furniture, Cleaning, Other)
- A suggested Priority (1 - Urgent, 2 - High, 3 - Normal, 4 - Low),
  where Urgent means a risk to safety or a building that can't be used
- A one-sentence summary of the problem
- A short reason for the suggestions

Add a field called AI summary (string) to the Issue table to hold the
summary. Coordinators can use the skill from the Issue form and must be
able to change any suggestion.

Show me the plan before building.

Then test it. When the build completes, confirm the installation. Open Now Assist Skill Kit and test the skill against several of your sample issues before publishing it. Try:

  • a clear description ("The tap in the second-floor kitchen won't stop running")
  • a vague one ("It's freezing in here")
  • one that should be Urgent ("Exposed wires hanging from the ceiling by the lifts")

If the suggestions are off, refine the instructions in a new prompt. For example: "Update the Issue triage suggestion skill: anything mentioning water leaking onto electrical equipment is always 1 - Urgent and Electrical."

Step 3: Build the agent

Start a new conversation once the skill is published.

Prompt
In the Workplace Issue Reporter app, create an AI agent called
Issue triage agent.

Goal: when a new Issue is created without a Category, triage it so it
reaches the right team quickly.

The agent should:
1. Use the published Issue triage suggestion skill to get a category,
   priority and summary.
2. Set the Category, Priority and AI summary on the Issue. Setting the
   Category routes it through the existing Category routing rule.
3. Search for open Issues at the same Location with a similar
   description. If it finds any, set a new field called Possible
   duplicate of (reference to Issue) and mention them in a work note.
4. Add an entry to the Work notes field explaining what it did and why.

The agent must never resolve, close or delete an Issue, or change
Reported by. Coordinators decide what to do with possible duplicates.

Show me the plan before building.

Then test it:

  1. When the build completes, confirm the installation.

  2. Open AI Agent Studio and review the agent's properties.

  3. Use the built-in testing tools to check the full process works and the agent's tools behave as expected.

  4. Activate the agent's triggers in AI Agent Studio. The agent is published straight away, but its triggers aren't switched on automatically. If your agent "does nothing", check this first.

  5. Report a few new issues as a test reporter, including one that repeats an existing issue, and check the results.

When things go wrong

What's happening What to do
Build Agent says it can't create agents or skills Ask a mentor to check Now Assist for App Engine is enabled.
The agent doesn't run when an issue is created Check its triggers are activated in AI Agent Studio.
Suggestions are inconsistent Add clearer definitions and examples to the skill instructions. Test again in Now Assist Skill Kit.
The agent finds too many duplicates Tighten the rule in your prompt, for example: same location, still open, and created in the last 7 days.
The agent does something it shouldn't Roll back to a checkpoint and add a "must never" line to your prompt.

Showing AI in your demo

  • Show the before and after. Report an issue, then show it categorised, prioritised and routed without anyone touching it.
  • Show the reasoning. Open the work note so the judges see why the agent did what it did.
  • Show people in control. Change one of the agent's suggestions as the coordinator.
  • Have a backup. Keep one issue the agent has already triaged, in case a live run is slow.
