Bad, OK and good prompts

The same idea can be prompted in very different ways. This page shows a bad, an OK and a good prompt for the kinds of thing you'll ask Build Agent to do, all using the Workplace Issue Reporter example from Guide 3.

What makes a prompt good

A good prompt covers five things:

Ask yourself Example
Where Which app, table or page? "In the Workplace Issue Reporter app..."
What What exactly should be built? Fields with types, states, roles
Who and why Who uses it, and what for? "So coordinators can triage new issues"
Rules What must always or never happen? "Never allow... without..."
Guardrails What must not change, and how should it proceed? "Don't change the table structure. Show me the plan first."

A bad prompt has none of these, so Build Agent guesses everything. An OK prompt says what to build, but leaves the details, rules and guardrails to chance. A good prompt covers all five, and works first time far more often.

Data tables

Bad prompt
Make a table for issues.
OK prompt
Create an Issue table with a description, location, category, priority
and status.
Good prompt
In the Workplace Issue Reporter app, create a table called Issue with
these fields:
- Number (auto-number with prefix WPI)
- Short description (string, mandatory)
- Description (long string, mandatory)
- Location (reference to cmn_location, mandatory)
- Category (choice: Electrical, Plumbing, Heating and cooling,
  Furniture, Cleaning, Other)
- Priority (choice: 1 - Urgent, 2 - High, 3 - Normal, 4 - Low;
  default 3 - Normal)
- State (choice: New, Assigned, In progress, On hold, Resolved,
  Closed; default New)
- Reported by (reference to sys_user, default current user)

Create a plan first and wait for my approval before building.

Why the good one works: every field has a type, the choices are listed, defaults and mandatory fields are stated, and it reuses platform tables (cmn_location, sys_user) instead of inventing its own.

User interface

Bad prompt
Make it look nice.
OK prompt
Create a form for people to report issues and a list where they can
see their issues.
Good prompt
In the Workplace Issue Reporter app, create the experience for
reporters (users with only the workplace_reporter role):

- A report form showing only Short description, Description and
  Location, in that order. Short description should have the hint
  "For example: Heating not working in room 3B".
- A "My issues" list showing their own issues, newest first, with
  Number, Short description, State and Updated.
- Reporters must not see Assignment group, Assigned to or Work notes.

I've attached a sketch of the form. Show me the plan before making
changes.

Why the good one works: it says who the screen is for, which fields appear and in what order, what must be hidden, and includes a sketch. "Nice" means nothing to an AI.

Process flow

Bad prompt
Add a workflow.
OK prompt
Issues should go from New to Assigned to In progress to Resolved to
Closed.
Good prompt
In the Workplace Issue Reporter app, add the issue lifecycle:

- New issues start in New.
- When the Category is set or changed, look up the Assignment group in
  the Category routing table, set it on the issue, and move it to
  Assigned.
- Fixers can move an Assigned issue to In progress, and an In progress
  issue to On hold or Resolved.
- Moving to On hold requires a comment in Work notes explaining why.
- The reporter can confirm a Resolved issue is fixed, which moves it
  to Closed. Coordinators can also close Resolved issues.
- No other state changes are allowed.

In your plan, explain which platform features you'll use for each step.
Don't change the table structure.

Why the good one works: it describes the trigger for every step, who can make each change, and what isn't allowed. Asking Build Agent to explain its approach in the plan helps you spot problems before anything is built.

Rules and validation

Bad prompt
Make sure the data is valid.
OK prompt
Issues should have resolution notes when they're resolved.
Good prompt
In the Workplace Issue Reporter app, add these rules to the Issue
table. Each should stop the record being saved and show the message
in brackets:

1. Never allow the State to be Resolved without Resolution notes
   ("Add resolution notes before resolving this issue").
2. Assigned to must be a member of the Assignment group
   ("Choose someone from the assigned team").
3. Users with only the workplace_reporter role can't change Priority,
   Category, Assignment group or Assigned to.

Show me the plan before making changes.

Why the good one works: each rule is a clear "never" or "must" sentence, with the exact message users will see. Numbered rules are easy to test one by one.

Notifications

Bad prompt
Send emails when things happen.
OK prompt
Email the reporter when their issue is resolved.
Good prompt
In the Workplace Issue Reporter app, add these email notifications:

1. When an Issue changes to Resolved: email the Reported by user.
   Subject: "Your issue [Number] has been resolved". Include the Short
   description, the Resolution notes, and a line asking them to
   confirm the fix.
2. When an Issue is created or changed to 1 - Urgent: email users with
   the workplace_coordinator role straight away.
3. When the Assignment group changes: email the members of the new
   Assignment group.

Don't send a notification to the person who made the change.

Why the good one works: each notification has a trigger, recipients and content. The last line heads off a common annoyance.

Roles and access

Bad prompt
Add security.
OK prompt
Reporters should only see their own issues. Coordinators can see
everything.
Good prompt
In the Workplace Issue Reporter app, set up these roles and access
controls:

- workplace_reporter: create Issues; read and update only Issues where
  Reported by is them; can update only Description, and can confirm a
  Resolved issue is fixed.
- workplace_fixer: read all Issues; update Issues where Assignment
  group is one of their groups.
- workplace_coordinator: read, create and update all Issues; create,
  read, update and delete Category routing records.

No one can delete Issues. Show me the plan before building, listing
each access control you'll create.

Why the good one works: it covers create, read, update and delete for every role, including the conditions ("where Reported by is them"). Asking for a list of access controls makes the plan easy to check.

Test data

Bad prompt
Add some test data.
OK prompt
Create 10 sample issues for testing.
Good prompt
Create sample data for the Workplace Issue Reporter app. Use fictional
names and values only.

- 3 assignment groups: Building services, Workplace team and Cleaning
  services, with Category routing records for every category.
- 4 test users: 2 reporters, 1 fixer in Building services, and
  1 coordinator.
- 15 Issues across every State and Category, written the way real
  people describe problems ("It's freezing in the meeting room
  again"). Include 3 reports of the same heating problem at the same
  location, and 3 with no Category.

Why the good one works: realistic, varied data lets you test every path, and the deliberate duplicates give the AI agent something to find later.

Fixing something that's wrong

Bad prompt
It's broken. Fix it.
OK prompt
The routing isn't working. Please fix it.
Good prompt
In the Workplace Issue Reporter app, routing isn't working.

What I did: logged in as the coordinator, opened WPI0001005 (State:
New, no Category) and set the Category to Plumbing.
What I expected: Assignment group set to Building services and State
changed to Assigned.
What happened: Category saved, but Assignment group is empty and
State is still New.

Find the cause and explain it before changing anything.

Why the good one works: it gives the steps, the expected result and the actual result, like a good bug report. Asking for the cause first stops Build Agent making random changes.

AI skill

Bad prompt
Add AI.
OK prompt
Create an AI skill that categorises issues.
Good prompt
In the Workplace Issue Reporter app, create an AI skill called Issue
triage suggestion.

Input: the Short description, Description and Location of an Issue.
Output:
- a suggested Category (one of: Electrical, Plumbing, Heating and
  cooling, Furniture, Cleaning, Other)
- a suggested Priority, where 1 - Urgent means a risk to safety or a
  building that can't be used
- a one-sentence summary of the problem
- a short reason for the suggestions

Coordinators can use it from the Issue form and must be able to change
any suggestion. Show me the plan before building.

Why the good one works: it defines the inputs, the exact outputs, the allowed values and what "Urgent" means. A skill is only as consistent as its definitions.

AI agent

Bad prompt
Make an agent that handles issues.
OK prompt
Create an agent that triages new issues and finds duplicates.
Good prompt
In the Workplace Issue Reporter app, create an AI agent called Issue
triage agent.

Goal: when a new Issue is created without a Category, triage it so it
reaches the right team quickly.

The agent should:
1. Use the Issue triage suggestion skill to get a category, priority
   and summary, and set them on the Issue.
2. Search for open Issues at the same Location with a similar
   description, created in the last 7 days. If it finds any, set
   Possible duplicate of and mention them in Work notes.
3. Add an entry to Work notes explaining what it did and why.

The agent must never resolve, close or delete an Issue, or change
Reported by. Show me the plan before building.

Why the good one works: it has a goal, a trigger, numbered steps, clear limits on what "similar" means, and firm "must never" rules. An agent with vague instructions makes vague decisions.
